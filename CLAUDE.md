# CC:Tweaked TypeScript

## Project Overview

TypeScript library for CC:Tweaked (ComputerCraft) Minecraft mod.
Compiles to Lua 5.1 via typescript-to-lua (tstl).
Compiled Lua files are committed to the repo so CC:Tweaked computers can download them directly.

## Build & Run

- `npm run build` - Clean build, compile TypeScript to Lua, generate manifest.json
- `npm run lint` - Check code with Biome
- `npm run lint:fix` - Auto-fix lint issues
- `npm run format` - Format code with Biome
- `npm run clean` - Remove build output
- `npm run release` - Patch version bump, build, commit, and tag
- `npm run release:minor` - Minor version bump
- `npm run release:major` - Major version bump

## Architecture

```
src/
  types/
    cc-missing.d.ts    Lua builtins + CC:Tweaked APIs missing from computercraft-types
  lib/
    manifest.ts        Shared types/utils for installer and updater (HTTP, file I/O, manifest ops)
    updater.ts         Auto-update library — checkForUpdates() for scripts
    turtle/
      bot.ts           Turtle Bot class — position tracking, fuel, pathfinding, movement history
      detect.ts        isTurtle(), requireTurtle(), getTurtleInfo()
      navigation.ts    Position, Direction types, turn/move math helpers
  scripts/
    hello-world.ts     Simple test script
    installer.ts       In-game installer/updater (self-contained, no imports)
scripts/
  generate-manifest.ts  Node.js — scans build/ and generates manifest.json
  release.ts            Node.js — version bump, build, git commit + tag
build/                  Compiled Lua output (committed for in-game downloading)
manifest.json           Auto-generated file listing, descriptions preserved across rebuilds
```

## Key Constraints

- Target runtime is Lua 5.1 inside ComputerCraft (NOT Node.js)
- Do NOT add @types/node — it conflicts with CC:Tweaked globals (fs, os)
- All globals come from computercraft-types + src/types/cc-missing.d.ts
- `noImplicitSelf: true` in tstl config — CC APIs don't use Lua's colon syntax
- computercraft-types has bugs: HTTP interface missing @noSelf — we redeclare `http` as a namespace in cc-missing.d.ts
- cc-missing.d.ts also declares Lua builtins (error, assert, pcall, pairs, string.find, etc.)
- build/ directory is NOT gitignored — compiled Lua is committed for distribution
- `luaLibImport: "require-minimal"` — only generates polyfills actually used, keeps bundle tiny
- Self-contained scripts (like installer.ts) must NOT import from src/lib/
- Use `for...in` loops to iterate over Records — tstl compiles these to Lua `pairs()` calls

## Installer System

- `src/scripts/installer.ts` — in-game installer, fully self-contained (no lib imports)
- `src/lib/manifest.ts` — shared manifest types and utilities (used by updater, NOT by installer)
- `src/lib/updater.ts` — auto-update library, wrapped in pcall so it never crashes the calling script
- `manifest.json` — auto-generated by `scripts/generate-manifest.ts`, version is a simple counter incremented by release script
- Bootstrap: `wget https://raw.githubusercontent.com/Haidy777/cc-tweaked-typescript/refs/heads/main/build/scripts/installer.lua installer`
- Commands: `installer list`, `installer install <name>`, `installer install all`, `installer update`, `installer self-update`
- lualib_bundle.lua is auto-downloaded when installing scripts that need it
- Descriptions in manifest.json are preserved across rebuilds

## Code Conventions

- Single quotes, no semicolons, 2-space indent, curly braces required (enforced by Biome)
- Prefer `const` over `let`
- Template literals over string concatenation (useTemplate rule)
- Types in src/types/ are declaration files (.d.ts) — no runtime code
- Lib modules in src/lib/ export reusable classes and functions
- Scripts in src/scripts/ are entry points — they import from lib/ and run immediately
- Turtle-specific libs go in src/lib/turtle/

## Testing

No test framework — the code runs inside Minecraft or CraftOS-PC. Test by:
1. `npm run build`
2. Copy the .lua file from build/ to the ComputerCraft computer's directory
3. Run the program in-game or in CraftOS-PC

## Common Patterns

- Peripheral wrapping: `const [device] = peripheral.find<MyType>("peripheral_name")`
- Event handling: `const [event, ...args] = os.pullEvent("event_name")`
- File I/O: Use CC's `fs.open()`, not Node fs
- Script arguments: `const args = [...$vararg] as string[]`
- Iterating Records: `for (const name in obj) { const val = obj[name] }`
- Auto-updates: `import { checkForUpdates } from './lib/updater'; checkForUpdates()`
- Turtle guard: `import { requireTurtle } from './lib/turtle/detect'; const t = requireTurtle()`
